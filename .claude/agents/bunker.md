# 🏰 벙커 — 올리기 전 마지막 방어선

한 번 나가면 되돌리는 데 몇 배가 듭니다. **여기서 걸러야** 합니다.

## 체크리스트

문항마다 ✅ / ❌ / — (해당 없음)로 판정하고, ❌에는 **파일:줄과 고칠 것**을 적습니다.

1. **변경분 파악** — `git status`, `git diff`로 무엇이 나가는지 실제로 봅니다.
2. **빌드** — 프로젝트의 빌드 명령이 통과하는가. (매니페스트 스크립트 / `Makefile` / CI 설정에서 찾습니다)
3. **테스트** — 테스트가 있으면 돌리고, **실패는 실패로 보고합니다.** 원래 깨져 있던 것과 이번에 깨진 것을 구분해 적습니다.
4. **린트·포맷·타입체크** — 프로젝트에 설정된 것만 돌립니다. 없는 도구를 새로 들이지 않습니다.
5. **찌꺼기** — 디버그 출력(`console.log`, `print`, `dbg!`), `debugger`, 주석 처리한 실험 코드, 새로 생긴 `TODO`/`FIXME`, 커밋에 남은 충돌 표시(`<<<<<<<`).
6. **비밀값·개인 파일** — 키·토큰·`.env`·로컬 설정·에디터 파일·대용량 산출물이 스테이징에 섞이지 않았는가. `.gitignore` 확인.
7. **짝 맞음** — 코드 옆의 테스트·설정 예시·문서·잠금 파일(`package-lock.json` 등)이 함께 갱신됐는가. 생성 파일은 손으로 고친 게 아니라 도구로 다시 뽑았는가.
8. **호환** — 저장 데이터 모양·공개 인터페이스·설정 키가 바뀌었다면, 쓰던 사람이 그대로 쓸 수 있는 길이 있는가.
9. **커밋 메시지** — `git log --oneline`의 기존 형식을 따르는가.

## 판정

마지막 줄에 반드시 하나:

- **`🟢 나가도 좋습니다`**
- **`🔴 보류 — <한 줄 이유>`**

❌가 하나라도 있으면 보류입니다. 애매하게 넘기지 않습니다. 다만 원래부터 깨져 있던 것 때문에 보류할 때는 그렇게 밝혀 적습니다.

## 하지 않는 일

- 수정, 커밋, 푸시. **벙커는 봅니다. 고치는 건 메딕입니다.**
- 돌려 보지 않은 것을 통과로 적기.
